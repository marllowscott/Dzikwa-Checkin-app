# Plan: Implement Floating Add Button for Universal Door

## Overview
Implement a floating "Add New Person" button for the Dzikwa Check-In System's public Universal Door workflow. This allows guards to quickly add new people when searches fail, without requiring admin access.

## Current State Analysis
- **Existing Domains**: Employees, Guests, Workshop Guests, Sadza Recipients, Children
- **Search Function**: `searchAllDomains` in `supabase.ts` covers all domains except Children
- **Add Forms**: Embedded in admin pages (AdminDashboard, ChildrenPage, WorkshopPage, SadzaStatsPage)
- **Check-In Logic**: Unified handlers in Index.tsx for all domains
- **UI**: CheckInForm component handles search and check-in/out

## Issues Identified
- Children domain not included in universal search
- Add forms are not reusable components
- No dynamic form loading system
- No floating UI for quick adds

## Implementation Plan

### Phase 1: Infrastructure Updates
1. **Update Search Function**
   - Add children search to `searchAllDomains` in `src/lib/supabase.ts`
   - Include `dzikwa_children` table with domain 'children' and label 'Children'

2. **Extract Reusable Form Components**
   - Create `src/components/forms/AddEmployeeForm.tsx`
   - Create `src/components/forms/AddGuestForm.tsx`
   - Create `src/components/forms/AddWorkshopGuestForm.tsx`
   - Create `src/components/forms/AddChildForm.tsx`
   - Create `src/components/forms/AddSadzaRecipientForm.tsx`
   - Each component should accept `onSuccess` callback for post-add actions

### Phase 2: Floating UI Components
3. **Create Floating Add Button**
   - `src/components/universal-door/FloatingAddButton.tsx`
   - Fixed position bottom-right
   - Circular design with plus icon
   - Elevated shadow, smooth animations
   - Mobile-friendly touch target

4. **Create Domain Selector Modal**
   - `src/components/universal-door/DomainSelectorModal.tsx`
   - Displays all domains as cards
   - Each card: icon, name, description
   - Domains: Employees, Guests, Workshops, Children, Sadza Stats
   - Bottom sheet or modal design

5. **Create Dynamic Form Loader**
   - `src/components/universal-door/DynamicDomainForm.tsx`
   - Conditionally renders appropriate form based on selected domain
   - Handles form submission and success callbacks
   - Includes automatic check-in after successful add

### Phase 3: Integration
6. **Update Index Page**
   - Import and add FloatingAddButton to Index.tsx
   - Position above existing CheckInForm
   - Ensure proper z-index layering

7. **Update Check-In Logic**
   - Extend Index.tsx handlers to support children domain
   - Add children check-in/check-out logic using existing patterns

### Phase 4: Testing & Polish
8. **UI/UX Testing**
   - Verify mobile responsiveness
   - Test smooth animations and transitions
   - Ensure backdrop blur and proper spacing

9. **Functionality Testing**
   - Test add + immediate check-in flow
   - Verify all domains work correctly
   - Test error handling and validation

10. **Security Verification**
    - Confirm no admin access required
    - Verify only add/submit permissions for guards
    - Ensure no edit/delete/export capabilities exposed
